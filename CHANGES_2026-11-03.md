# Noetic Field (Python) — patch of 2026-11-03

The same bug classes that were found and fixed in the browser edition, fixed here, plus what independent reviews and a mutation run found in the patch itself.

- **Backup of the original code:** `_backup_before_patch_2026-11-03/` (every `.py` file and `requirements.txt` as they were). To go back, copy those files over the ones in this folder and delete `llm_json.py`, `consoleutil.py` and `tests/`.
- **Run the tests:** `pip install -r requirements-dev.txt`, then `python -m pytest tests -q` from this folder. They use no network and no API key, and never touch your real `noetic_state.json` (the test setup points `NOETIC_STATE_FILE` at a temp file).
- **Not done:** no call has ever been made to the live Anthropic API. See "What was and was not checked".
- **Later change (2026-11-04):** model calls now go through a provider layer (Anthropic or OpenRouter, a model per agent); see `PROVIDERS_2026-11-04.md`. The suite is now 715 tests (704 and 11 skipped without the `openai` package); the figures in this file are as of 2026-11-03.

## What was wrong in the original

Each of these was reproduced on the original code with identical inputs (13 of 14 probes showed the defect; the same probes show none on the patched code):

| Defect | What it did |
|---|---|
| An unreadable or unrecognized values-check reply counted as **pass** | A broken reply, or a reply with an unknown status, passed the response. A `}` inside a string in a valid veto turned the veto into a pass. |
| An unreadable narration reply said the explanation **matched** | The fallback was `explanation_matches_reasoning: True`. |
| Cut-off JSON was shown to you as the answer | The raw `{"reasoning_steps": ...` text became the response. |
| Confidence `"nan"` became 1.0, `85` became 1.0, `"85%"` became 0.5 | Certainty from garbage; percentages misread. |
| A failed first model call left an orphaned user turn | The conversation then held a question with no answer. |
| One reply could store every divergence note as an insight | Ten notes evicted the 50-insight list in five interactions. |
| `add_value` accepted empty, placeholder and duplicate values | They went straight into the values prompt. |
| No limit on message size | 50,000 characters went to the model. |
| The values check was shown C's reasoning when C's JSON was broken | The raw JSON, steps included, was passed along. |

## What changed, by file

- **`llm_json.py` (new).** Total JSON extraction and coercion: only top-level `{...}` spans, string-aware brace matching, repair of cut-off replies (flagged `repaired`), tolerance for stray backslashes and trailing commas, NaN/Infinity/arrays rejected, huge integers read as "not a usable number", no quadratic regexes. `scrub()` replaces control characters (so model text cannot drive a terminal) and lone surrogates. `fence()` wraps untrusted text in prompts and turns every `<` inside it into `&lt;`.
- **`state.py`.** Sanitizing `load()` (nothing on disk is trusted; wrong types, huge numbers and junk are cleaned; defaults are never aliased; a UTF-8 byte-order mark is accepted; unknown keys are kept only if they are small, plain JSON). Atomic `save()` that returns the signature of what it wrote, with a retry of about one second for Windows file locks, and an optional check right before the rename that the file is still the one the change was based on. An unreadable file is moved to `noetic_state.json.bak-<time>-<pid>-<ns>` (a name nothing else can have; the move waits out a lock for about a second; the newest 20 such backups are kept); if it cannot be moved, `load()` raises instead of overwriting it. Smoothed per-domain confidence, caps on everything, `NOETIC_STATE_FILE`, `file_signature()`, `try_load()`, `fresh_state()`, `is_blank()`.
- **`conversation.py`.** Per-conversation lock, atomic user+assistant pairs, history that always starts on a user turn; an assistant turn shows its assessment whenever it has one.
- **`agents.py`.** One `call_model` that turns every SDK failure, refusal and empty reply into `AgentError`; fenced prompts; fail-visible fallbacks (V → `unchecked`, N → `unknown` / `None`); V is given only the user's message and C's response (no steps, no confidence, no uncertainty flags) and never an unreadable C reply. A check that contradicts itself is resolved toward visibility for the spellings it reads (the first word of a short answer: "No.", false, "does not follow"; a recommendation that starts with "regenerate" or "suggest modif"); other spellings still pass: N saying "does not follow" with risk `low` becomes `medium`; V saying `pass` while reporting hidden uncertainty or recommending a change becomes `flag`. A V or N reply that was cut off or had to be repaired may raise a concern but never clear one (a pass becomes `unchecked`, low risk becomes `unknown`). A V reply with no recognizable status is `unchecked`. A recommendation given as a list counts item by item. Error messages are scrubbed.
- **`self_review.py`.** Starts at most once per ten interactions, from the uncapped counter (a failed review is not retried); a review that failed to parse, was cut off or was repaired stores nothing and says why; domain flags only lower confidence, once per domain, only for domains that exist; signals keyed by a hash of the text, so different signals almost never share a key; the values-tension pattern is kept.
- **`orchestrator.py`.** C first, then N and V in parallel, each guarded; copy-on-write commit (a failed save leaves memory and disk in agreement); the exchange enters the conversation only after the state is saved; the review is decided once under the lock and run outside it; before reading or writing it adopts changes another process committed, and a change that finds a newer file underneath it is made again on top of that file (up to 12 tries in all, with a short random pause); a missing, damaged or reset file is written back from memory when the process holds history; cut-off, repaired and empty replies are not recorded as measurements; `NoeticOrchestrator(count_session=False)` for one-shot commands.
- **`api.py`.** Bounded sessions that are never evicted while in use, `AgentError` → 502, bad input → 400, a malformed request → 422 whose body never repeats what was sent, reports that read the live state (or, before the first write, the file, without creating anything).
- **`audit.py`, `cli.py`, `consoleutil.py`.** Audit reports only read (a missing or unreadable file is reported on stderr, not created or moved). The CLI checks its arguments before touching anything, takes the text after `--insight` or `--value` word for word, applies the API's limits and cleaning, and does not count `--self`, `--insight` or `--value` as sessions; a state file that cannot be read or written is one line of text, not a traceback. Input and output are UTF-8, so a pipe on Windows cannot garble a message or crash on `█` or `≈`.
- **`tests/`.** The offline suite, including the real Anthropic SDK against a local stub server.

## Round three: what the third review found, and what was done

Three Sonnet reviewers, each required to reproduce what they reported, filed 24 findings (2 high, 8 medium, 14 low); two pairs overlap. Each was reproduced on the code as it stood, fixed, and pinned by a test in `tests/test_round3.py`. Run against the code as the reviewers saw it, 93 of the file's 142 tests fail (12 of those only because the function they pin did not exist yet) and 49 pass: those are controls that pin behaviour that was already right.

| Finding | Severity | Fix |
|---|---|---|
| A process that started on a damaged file wrote a blank one, and every running process adopted the blank and lost its in-memory history | high | A file that reads as blank while the process holds history is not adopted: the process writes its own state back. |
| A V or N reply that was cut off or repaired was logged and shown as a clean pass or low risk | high | Such a reply may raise a concern but never clear one: `pass` becomes `unchecked`, `low` becomes `unknown`; flag, veto, medium and high stand. A repaired C reply now says so under the answer. |
| A deleted state file was not written back by a read | medium | Any call writes our state back when the file is gone and we hold history. A process with no history creates nothing by looking. |
| A save whose rename had to wait for a locked file overwrote a newer commit (5 of 5 trials lost an acknowledged write) | medium | The save checks, before every rename attempt, that the file is still the one the change was based on; if not, nothing is written and the change is made again on top of the newer file (random pause, up to 12 tries). |
| Moving a damaged file aside gave up at the first lock, and the next commit then overwrote the file with no backup | medium | The move waits out a lock for about a second; if it still fails the request raises and the file is never written over. |
| A V reply with an unrecognized status was stored as an invisible `flag` | medium | It is `unchecked` and counts as a parse issue. |
| A rejected request could turn into a 500 (`NaN`, `1e999`, non-UTF-8 bytes, nesting 1,000 deep) | medium | The 422 body no longer repeats what was sent. |
| The first API call, even a read, created the orchestrator, counted a session and could move a damaged file | medium | Before the first chat or edit, reads use the file as it is and touch nothing; after that they go through the orchestrator, which adopts other processes' changes and can write the state back. |
| `--insight` and `--value` silently dropped `--verbose` from the text, and `-h` inside it printed usage and saved nothing | medium | The text after the flag is stored exactly as typed. |
| Backups of damaged files grew without bound (401 corruptions, 401 files) | low | The newest 20 are kept; only files named the way the program names them are ever deleted. |
| A killed or interrupted save left temp files | low | Cleaned on Ctrl-C too; stale ones (over an hour old) are swept at start. |
| `snapshot()` said it never touches the file, but it can repair it | low | Documented. |
| A deeply nested unknown key made every start fail; a 5,000-digit integer set the whole file aside | low | Unknown keys are kept only if small plain JSON; huge integers read as "not a usable number". |
| N and V contradiction rules recognized only exact spellings (`regenerate!`, `["regenerate"]`, `False.`, `does not follow`) | low | Near spellings read like exact ones. |
| A reply cut inside an escaped surrogate pair left a replacement character | low | Fixed. |
| Texts told to the model did not match the code (insight sources, what a veto does, how many insights S sees) | low | Corrected. |
| `insufficient data` was stored as a values tension and shown to C; a tension was hidden when the review gave no health text; the audit said "not yet reviewed" after a review | low | Non-findings are not stored; the tension shows regardless; the audit goes by `last_review_at`. |
| Control characters alone counted as text; the API and the CLI measured length differently | low | One cleaning rule for the API, the CLI and the state. |
| A byte-order mark hid the first command; closed stdin or stdout ended in a traceback after a session was counted | low | Handled; no session is counted when nothing can be read. |
| A failed save in the interactive CLI ended the session with a traceback | low | One line, and the loop goes on. |
| The verbose confidence note said "could not be read as structured output" when the reply was fine | low | The wording follows what happened. |
| The audit of a missing file looked like a brand-new system | low | A notice on stderr. |

## What the system now tells itself

| Old wording | What the source says | Now |
|---|---|---|
| "TWO separate circuits": computation and narration (narration prompt) | No paper describes a narration circuit. There are examples where a model's account differs from its mechanism and examples where it matches; how often is not measured. | The narration check compares written steps with the written answer and says it cannot see internals. |
| "Reward-model approval-seeking fires on 100% of Human/Assistant interactions" (values prompt, self-model) | One feature, in a model deliberately trained to exploit reward-model biases, was active on 100% of the dialogs tested (related features 19% to 100%). The authors think it was formed in finetuning. | Stated with that scope. The values prompt says only that models can be pulled toward what raters reward. |
| "75% of the computation is dark matter" (review prompt) | Not in the papers. | Removed; dark-matter signals are labelled hypotheses. |
| "Defaults are always active" / "ground state" (self-model) | A hypothesis, tied to chat-formatted prompts. | Hedged and sourced. |
| "Values agent ... this pull is not carried into its judgment" (self-model) | The values agent is the same underlying model; not seeing C's steps limits what it inherits, nothing more. | Corrected in this version and in the browser edition (awareness revision 2 there, so saved states pick up the new text). Revision 3 here: the text now also says the values agent reads only the response, never the steps or the stated confidence. |

## Behavior you may notice

- `confidence` may be "not reported" (`confidence_defaulted`), and is then never averaged in, never logged, and shown as `n/a` in the history C sees.
- A values check that could not run, was cut off with a pass, or could not be read shows as `unchecked`, with "values check unavailable" under the answer. A values `flag` is not itself written under the answer (a veto prefixes it; a detected approval-seeking pattern adds a note); it appears in `values_status`, in verbose output, in the audit reports and in the history C is shown.
- API: `/chat` returns extra fields (`confidence_defaulted`, `review_error`, `parse_issues`, `truncated`, and with `verbose` the `parse_status`); `/value` returns 400 when nothing was added; `/review` returns what was stored; empty or over-long input is 400, a malformed request 422, a failed model call 502.
- State file: entries gain `n`, `flagged_at`, `count`, `noted`, `last_review_at`, `last_review_tension`, `awareness_rev`. Old files load. An unreadable one is kept as a `.bak-...` file and a warning is logged.
- If the CLI and the API run at the same time on one `noetic_state.json`, each adopts the other's changes before it saves, and a save that finds a newer file underneath it is redone on top of that file. What remains is the time between the last check and the rename (microseconds); a guaranteed single writer would need a lock file. A damaged file that is set aside is kept as `.bak-...` (the newest 20); a file that was deleted or reset while a process holds history is written back from that process's memory.
- If the state file cannot be saved after the three model calls, the answer is discarded and the request raises (the calls are already paid for). Memory, disk and conversation stay consistent.

## After the audit: your decision on what the values check sees

- **The values check now sees only the user's message and C's response**, as in the browser edition. Before, it also saw C's claimed confidence and uncertainty flags (in an `author_report` block). Four edits in `agents.py`: the sentence in V's prompt that said what it sees, the "hidden uncertainty" bullet (it no longer says "beyond the confidence and flags the author reported"), the `author_report` block, and the sentence in C's prompt that told C what V reads. The self-model text says the same (awareness revision 3, so saved states pick up the new wording).
- **What this costs:** V can no longer compare the tone of an answer with the confidence its author stated. It judges tone against content alone. N still sees the steps, the confidence and the flags, so that comparison is made there.
- Five tests pin it (V's text holds none of the steps, the flags, the confidence or the domain, and its user part has exactly two blocks; C's prompt says V reads only the response; the self-model wording; a state saved at revision 2 picks up the new text). Each fails on the code before the change. The suite is now 640 tests (see the next section for the five added after).

## After the port: two gaps that a review of the browser port found in this edition too

An independent review of the browser edition's port of these fixes (three reviewers, each finding reproduced) also compared the two editions. It found two gaps that this edition shared. Both are fixed here and in the browser edition, with tests that fail on the code before (`tests/test_port_review.py`):

- **A values check that did not complete lost a concern it had stated.** A cut-off or repaired values reply that said `pass` became `unchecked`, as intended (it may raise a concern, never clear one), but the fallback shape also dropped `sycophancy_detected: true`, so the log, the audit and the note under the answer showed no sycophancy. The same happened when the status was unrecognized. The flag is now kept.
- **The fence now also escapes the small less-than sign (U+FE64).** Like the full-width one, Unicode compatibility normalization turns it into a real `<`; whether any layer between this program and the model normalizes was not tested.

Found and **not changed** (they are the same in both editions, and extending the first-word reading is a design change): a curly apostrophe (`Doesn’t follow`) or a leading article (`The explanation does not follow`) is not read as a "no"; a numeric string such as `"0.8"` is read by its first digit; a recommendation spelled `Suggested modifications`, `Regeneration recommended` or `re-generate` does not raise a `pass`; and repairing a 200,000-character malformed reply takes about half a second (replies are bounded by the output limit, about 8,000 characters for C, where it takes milliseconds).
